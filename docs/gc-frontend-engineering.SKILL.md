# Frontend engineering for The Gathering Co.

Stack: Next.js 16 App Router, React 19, TypeScript strict, Tailwind v4 (CSS-first), shadcn/ui on Radix, lucide-react, next/font, next-themes, sonner, Zod 4, Biome, Vitest, Playwright, pnpm. No database, no auth, no state library in phase 1. Read `docs/SPEC.md` first if it exists; it wins over this file on any conflict.

## Before you write code

1. Find the page or component that already does something similar and copy its shape.
2. Check `src/content/` for the data you need. Pages never define data inline.
3. Check `src/components/domain/` for a component that already renders this thing. Extend it before creating a new one.
4. Decide server or client (below). Default is server.

## Rendering rules

- Pages and layouts are server components. No `"use client"` on a page, ever.
- `"use client"` goes on the smallest leaf that needs state, effects, refs or event handlers (a form, a filter bar, the floating WhatsApp button). Lift the static shell above it.
- Static content pages use `generateStaticParams` and no dynamic APIs so they build to static HTML.
- `generateMetadata` on every page, via helpers in `src/lib/seo.ts`. Title pattern: `<Page> | The Gathering Co.`
- `loading.tsx` renders a skeleton, never a spinner. `error.tsx` says what happened and offers retry plus a link home.
- `next/image` for every raster image with explicit width and height. Decorative images get `alt=""`. Hero and above-the-fold images get `priority`.

## Component tiers (do not mix)

| Tier | Folder | Rule |
| --- | --- | --- |
| Primitives | `src/components/ui` | Generated by `pnpm dlx shadcn@latest add <name>`. Vendor code. Lint-excluded. Edit only for cross-cutting props such as `pending` on Button |
| Domain | `src/components/domain` | The app vocabulary: `ItemCard`, `OccasionCard`, `EnquireButton`, `WhatsAppButton`, `SocialLinks`, `SectionCard`, `PageHeader`, `Eyebrow`, `Divider`, `EmptyState`, `FeatureStrip`, `Faq`. Accept domain types from `src/domain/types.ts`, never raw data shapes. Each list component owns its empty state |
| Shell | `src/components/shell` | `SiteHeader`, `SiteFooter`, `MobileNav`, `nav.ts`. `nav.ts` is the single nav list |
| Pages | `src/app/(site)/**` | Compose domain and shell components. Pages do not style; they lay out |

A hex colour, a pixel radius or a font name inside a component is a review failure. Everything comes from tokens in `globals.css` (`bg-cream`, `text-cocoa`, `border-hairline`, `display`, `script`, `eyebrow`).

## Data and config

- `src/content/site.ts` reads `NEXT_PUBLIC_*` env vars once, validates with Zod at import, exports `SITE`. It is the only place a contact detail or social URL exists.
- `src/content/catalogue.ts`, `occasions.ts`, `faq.ts` export typed arrays and lookups (`getItem(slug)`, `listItems(category?)`). Pages call these and nothing lower. Phase 2 swaps the file for a repository behind the same signatures.
- `src/lib/whatsapp.ts` exports `whatsappUrl(message?)`. All WhatsApp links go through it.
- Dummy data is marked `// DUMMY` in code and `[TODO]` in copy. It must look real: plausible item names, GBP prices, Newcastle postcodes.

## Forms

- Schema in `src/domain/schemas.ts` (Zod). The form calls `schema.safeParse` on submit and maps `error.flatten().fieldErrors` to per-field messages.
- Native `useState` per field. react-hook-form only if a form has more than roughly eight fields.
- Submit button takes `pending`; disable and show a spinner while submitting. No double submit.
- The enquiry form builds a multi-line WhatsApp message, opens `whatsappUrl(message)` in a new tab, and offers "Copy message" and a `mailto:` fallback. No network call in phase 1.
- Dialogs and sheets are keyed on the record id so state resets per record without effects.

## Styling

- Tailwind utilities only; no CSS modules, no inline style objects except for dynamic values that cannot be classes.
- Mobile first. Gutters 16 px, content column capped at 1100 px, bottom padding for the safe area and the floating button.
- Spacing scale: 4, 8, 12, 16, 24, 32, 48, 64, 96. Section padding 48 on mobile, 96 on desktop.
- `cn()` from `src/lib/utils.ts` for conditional classes.
- Dark mode via `.dark` token swap; do not write `dark:` variants in components unless a token cannot express it.

## Accessibility and performance floor

- Visible focus ring (`ring-tan`) on every interactive element. Tap targets at least 44 px.
- Contrast AA for all text on `cream`, `linen` and `surface`.
- Landmarks: one `main`, `nav` with `aria-label`, `footer`. Headings in order, one `h1` per page.
- `prefers-reduced-motion` disables all animation (handled in `globals.css`; do not add motion that bypasses it).
- No layout shift: every image has dimensions, fonts use `display: swap` with `size-adjust` fallbacks from next/font.
- Lighthouse mobile at 90 or above on performance, accessibility and SEO on every route.

## Testing

- Vitest for pure code: `whatsappUrl`, schemas, content lookups, `seo.ts`.
- Playwright smoke: load `/`, open an item, click Enquire, assert the `wa.me` href and prefilled text. Runs on Pixel 7 and desktop.
- `scripts/screenshots.mjs` renders every route at 390 and 1280 wide and fails on console errors. Run it before opening a PR.

## Definition of done for a frontend change

- [ ] Server or client decided deliberately; no `"use client"` on a page
- [ ] No literal colours, radii, fonts, contact details or data in components
- [ ] Empty, loading and error states handled where lists render
- [ ] Keyboard reachable, focus visible, headings in order
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` pass
- [ ] Screenshots reviewed at phone and desktop width
